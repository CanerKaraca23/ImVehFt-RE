# `terminate` EH4 scope-table relocation and Ghidra correction

Ghidra's `10017dde.json` shows `terminate` passing `(scope_table, 8)` to the injected `__SEH_prolog4`, reading `_terminate` at `[EAX+0x78]`, setting `[EBP-4]` to zero only around the user handler call, then setting it to `-2` before `_abort`. The PE table at `0x10028460` contains header dwords `(-2, 0, -40, 0)` followed by one scope record `(-2, 0x10017dfe, 0x10017e02)`. Original PE bytes confirm `0x10017dfe` is `xor eax,eax; inc eax; ret` (filter returns true) and `0x10017e02` is the EH landing pad that restores ESP from `[EBP-0x18]`, restores state `-2`, then calls `_abort`.

The previous candidate body was not a faithful implementation: its `_tiddata` struct put `_terminate` at offset 0 (emitted `mov eax,[eax]` rather than `[eax+0x78]`), and its ordinary C++ helper call emitted `add esp,8` after `__SEH_prolog4`, absent from Ghidra's sequence. It also passed the fixed preferred-base table address.

Replaced `src/functions/10017dde.cpp` with a naked x86 implementation matching the observed register/stack flow. The EH4 table is now a static 28-byte const record whose filter and landing-pad fields point to candidate symbols; fresh COFF disassembly shows two `DIR32` table relocations. The filter helper emits the same `xor/inc/ret` bytes; the landing-pad helper emits the same stack/state restoration and a relocatable `REL32` call to candidate `_abort`. The `terminate` object now uses the intended `[EAX+0x78]` access, makes no caller-side stack cleanup after the SEH prolog, and preserves the distinct no-handler versus returned-handler state paths. The 705-object diagnostic map resolves the scope-table storage, filter, landing-pad and `__SEH_prolog4` references to candidate objects.
