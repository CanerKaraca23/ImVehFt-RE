# PE data-relocation code-target site classification

Date: 2026-09-27. This supplements the whole-image PE HIGHLOW relocation
inventory. It classifies the 80 `.rdata`/`.data` sites whose stored `.text`
address is not an exact one of the 705 candidate function entries.

## Reproduction and evidence

The source inventory is
[`pe-data-relocation-target-coverage-current-2026-09-27.csv`](pe-data-relocation-target-coverage-current-2026-09-27.csv).
The 80 sites were queried against the saved ImVehFt Ghidra project with
Ghidra 12.1.3 `-noanalysis -readOnly` using
[`GhidraReadOnlyAddressSymbols.java`](../scripts/GhidraReadOnlyAddressSymbols.java).
The query output is
[`pe-relocation-code-target-sites-ghidra-2026-09-27.csv`](pe-relocation-code-target-sites-ghidra-2026-09-27.csv).
The full initializer range was byte-read from the original Ghidra program in
read-only mode; see
[`crt-init-array-entries-ghidra-2026-09-27.csv`](crt-init-array-entries-ghidra-2026-09-27.csv).
The 24-slot source/callback crosswalk is generated by
[`audit-crt-init-array.py`](../scripts/audit-crt-init-array.py) and recorded in
[`crt-init-array-source-crosswalk-2026-09-27.csv`](crt-init-array-source-crosswalk-2026-09-27.csv).
Target instruction windows were independently obtained by importing the exact
ASI into a temporary Ghidra project and decoding absent instruction units
in-memory; see
[`pe-relocation-code-target-disassembly-fresh-2026-09-27.csv`](pe-relocation-code-target-disassembly-fresh-2026-09-27.csv).
The callback entry bytes were also read from the saved project in read-only
mode; see
[`pe-relocation-registered-callback-entry-bytes-ghidra-2026-09-27.csv`](pe-relocation-registered-callback-entry-bytes-ghidra-2026-09-27.csv).
Ghidra export `10012c05.json` and the corresponding candidate source were
compared instruction-by-instruction for the CRT initializer traversal.

## Findings

- 80 unique relocation sites point into `.text`: 70 sites are in `.rdata`,
  and 10 sites are in `.data`.
- The 10 `.data` entries are the contiguous pointer slots
  `0x10029d40..0x10029d64` (stride 4), all initialized in the image to
  `0x1001af2b`. Ghidra references identify the table in
  `__initp_misc_cfltcvt_tab` and `__cfltcvt_init`, with reads in `__input_l`
  and `__output_l`. These are CRT floating-conversion dispatch entries, not
  ten candidate-function aliases. Their startup writes and consumers must be
  reconstructed as runtime state.
- Ghidra's `__cinit` at `0x10012c05` calls `__initterm_e`, registers
  `FUN_10016cec` with `_atexit`, then walks the exact half-open initializer
  range `[0x10022154, 0x100221b4)` in ascending 4-byte slots, invoking each
  nonzero pointer. A fresh byte read confirms **24 slots**: the first is null,
  the second points to candidate `FUN_10020870`, and the remaining 22 point to
  startup thunks from `0x100208d0` through `0x10020a60`. This verifies both the
  table bounds and execution order for this CRT path.
- Before that 24-slot array, `__cinit` calls `__initterm_e` on a separate
  six-slot range `[0x100221b8, 0x100221d0)`. It contains one null and five
  nonzero callbacks. Only `___initmbctable` maps to an exact candidate entry;
  the other four are binary-only CRT initialization bodies, two using the
  `IsProcessorFeaturePresent` import and two allocating/writing CRT state.
  Their return codes control whether later initialization proceeds. The
  full crosswalk and instruction evidence are in
  [`crt-initterm-e-array-crosswalk-2026-09-27.md`](crt-initterm-e-array-crosswalk-2026-09-27.md).
- Those 22 startup thunks call `_atexit` and register 22 callback addresses;
  the disassembly-to-source crosswalk maps all 22 to candidate TUs with
  objective PASS. The thunks themselves are not exact entries in the 705
  candidate map and are not present elsewhere under `src/`. `FUN_10020870`
  is a separate candidate initializer; its body also registers
  `thunk_FUN_100013e0` after initializing its list.
- A source-vs-Ghidra comparison found and corrected a real candidate semantic
  mismatch in `src/functions/10012c05.cpp`: it previously registered
  `FUN_10020870` as the `__cinit` exit callback, while the original pushes
  `0x10016cec` at `0x10012c48`. The candidate now registers
  `FUN_10016cec`; fresh object disassembly confirms it emits a reference to
  `_FUN_10016cec@0` before `__atexit`. Full strict compilation, structural
  objective verification, and whole-set parity were rerun after this change;
  see [`10012c05-atexit-registration-correction-2026-09-27.md`](10012c05-atexit-registration-correction-2026-09-27.md).
- The startup data itself is not defined by the 705-object archive:
  `DAT_10022154`, `DAT_100221b4`, `DAT_100221b8`, and `DAT_100221d0` each have
  undefined COFF references and no definitions in the candidate archive.
  Therefore the corrected callback and initializer TUs do not supply the
  table or its companion error-initializer bounds to a replacement image.
- The remaining `.rdata` sites are scattered across the section. Their
  targets include function-body interiors and short sequences that restore
  `ESP` from `[EBP-0x18]`, reset an exception-state slot, and terminate with
  `INT3` or transfer to a cleanup routine. This is consistent with compiler
  exception/funclet metadata and explains why some targets are not ordinary
  705 function entries. It is not sufficient to assign every scattered site
  to a specific SEH table: Ghidra currently represents most source slots as
  untyped bytes and has no incoming-reference records for them.
- These addresses must not be blindly aliased to the nearest candidate
  function. In particular, `0x10010888` starts with a register/context
  operation before candidate entry `0x1001088b`, and
  `0x10018a86` starts five bytes before candidate `0x10018a8b`; both candidate
  sources explicitly recover incoming register state. Redirecting such
  entries changes the calling convention/context.

## Link implication

This pass improves the inventory but does not close it. A replacement image
still needs the original `.rdata`/`.data` pointer tables, initialized values,
CRT startup registration/ordering, exception/funclet semantics, and relocation
treatment preserved coherently. The callback implementations exist in the
candidate set, but the 22 startup thunk functions and initializer data table
are not yet integrated into a replacement link. The separate `_initterm_e`
table also contains four noncandidate CRT initialization bodies and remains
unprovided. The current 705-object archive compiles, but it is not a loadable
plugin; do not test a diagnostic link in the game. Full link and runtime
validation remain open.
