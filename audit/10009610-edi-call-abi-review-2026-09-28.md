# `FUN_10009610` caller ABI review (2026-09-28)

## Finding

Do not convert the 16 calls in `src/functions/10009790.cpp` to ordinary C++
member calls yet. Ghidra exports `10009790.json` and `10009610.json` establish a
non-standard mixed-register call sequence that the current candidate source
does not express:

- `FUN_10009610` enters with `ECX = this`, `EDI = one of 16 GTA executable
  addresses`, and two stack arguments. Its epilogue is `RET 0xc`.
- At each of the 16 call sites, `10009790` loads a distinct `this` address in
  `ECX`, a distinct GTA address in `EDI`, then pushes `param_1` and `param_2`
  before the direct call. These values are visible at `0x1000979a..0x100098d0`
  in the Ghidra assembly export.
- `10009610` reads the incoming `EDI` (`MOV [ESI],EDI`), passes it to
  `FUN_10009060`, and later dereferences `EDI+5` for `FUN_10008e40`.

The apparent `__thiscall` signature omits this EDI input. An ordinary C++ call
can legally clobber EDI and would not preserve the target behavior. The existing
candidate body explicitly captures incoming EDI, but compiling that body with
Clang has already failed because its non-MSVC fallback cannot reliably bind an
incoming register value; see `build/clang-continuation-rerun2-20260927.json`.

## Correction and current verification

The initial source review did not catch the third stack slot: each caller
pushes three values and the target ends in `RET 0xc`, while the previous
two-argument candidate emitted `RET 8`. That was confirmed directly in
`dumpbin /disasm` output for the current pre-fix MSVC object. This was a real ABI
mismatch, not just an instrumentation limitation.

Both affected sources were backed up before editing. The target candidate now
declares an ignored third stack-cleanup parameter, and `10009790.cpp` performs
all 16 calls in explicit x86 assembly. Each sequence loads the Ghidra-observed
`ECX` and `EDI`, pushes all three stack values (including the per-call 4/6
cleanup-slot value), and calls a local naked entry shim. That shim directly
jumps to the C++ target symbol. Current object inspection confirms target
`RET 0xc`, 16 caller `REL32` relocations to
`_FUN_10009610_relocatable_entry`, and no absolute call to `0x10009610`.

contains 16 `DIR32` relocations to those candidate symbols and 16 `REL32`

no longer embedded in the caller.
