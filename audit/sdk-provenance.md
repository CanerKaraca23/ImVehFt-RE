# SDK provenance

The local reference binary `ImVehFt.asi` has an x86 PE header, a linker-version trace of 10.00, and a PE timestamp of 2014-05-23 20:08:32 UTC. It imports `d3dx9_43.dll` and the Windows system libraries, but no `plugin.dll`.

An earlier SDK probe recorded a dated September/October 2013 snapshot under `C:/Users/caner/Downloads/SA Plugin SDK`; that path is absent in the current filesystem recheck (2026-09-30), so those files are not available for a fresh build. The probe's recorded `plugin.lib` was an import library containing `__IMPORT_DESCRIPTOR_plugin` and expecting a separate `plugin.dll`; using it produced no DLL and 612 unresolved linker diagnostics. The historical SDK material currently available locally is the separate 2014-04-27 source snapshot under `C:/Users/caner/OneDrive/Documents/ImVehFt/_sdk_history/snapshot-2014-04-27`, described below. Neither SDK snapshot establishes the target's exact original build inputs.

The closest public historical Plugin-SDK line before the binary timestamp is the static-library work in the April 2014 history. The 2014-04-27 commit `888a67c1587ece1053a05f0cb6219a0c6c4dad0a` retains `PLUGIN_API` as a static implementation marker in `src/sdk/plugin/plugin.h`; the 2014-04-08 commit `d55b334629df248aec238f1d8e80673166bc7301` is the earlier commit explicitly titled `Static version is done`.

The 2014-04-27 source snapshot was built as an x86 static library with the installed VS2022 toolchain. All 91 SDK translation units compiled. Two local test-only compatibility edits were needed in `CallbackResetDevice.hpp`: correcting the MSVC naked-function return declaration and removing an unreachable GCC-only jump from the MSVC branch. The historical source tree remains a separate checkout; these edits do not change the 705 candidate sources.

The resulting `Plugin2014.lib` was added to the same strict 705-object diagnostic link used with the modern SDK. Before address shims, both probes reported 228 unresolved externals and produced no DLL. The first 2026-09-24 address-shim probe reached 208; intermediate snapshots reported 198 and 164. The latest 2026-09-26 probe after the x87-tail corrections reports 161 unique unresolved externals (201 linker error lines), still with no DLL. This is a symbol-resolution experiment, not proof that the SDK vintage or inferred call behavior matches the original build. See [`link-probe-2026-09-24.md`](link-probe-2026-09-24.md), [`candidate-correction-10003ba0-10003e60.md`](candidate-correction-10003ba0-10003e60.md), [`candidate-correction-100076d0.md`](candidate-correction-100076d0.md), [`candidate-correction-100099f0.md`](candidate-correction-100099f0.md), [`candidate-correction-100074d0.md`](candidate-correction-100074d0.md), [`candidate-correction-10005670.md`](candidate-correction-10005670.md), and [`candidate-corrections-2026-09-26.md`](candidate-corrections-2026-09-26.md).

This is provenance evidence, not proof that ImVehFt used one exact commit. The remaining blockers are chiefly GTA executable addresses, unresolved image globals/data, old CRT/EH ABI helpers, and missing original project inputs.

Therefore the presence of a current SDK improves access to modern headers/examples but does not supply the target's historical project configuration, the author's custom SDK/build fork, the original CRT/EH/linker choices, or a complete source project. The standalone 705-unit compile remains valid as a compile check; it is not a production `.asi` build. A diagnostic DLL still fails its original-address/layout audit and must not be loaded into the game.

A targeted x86 layout-probe attempt against this current checkout, configured with its `RW`/`GTASA` defines and current `rwcore.h` include paths under C++23 mode, confirms it is not a drop-in replacement for the 2014 layout evidence: `RwRaster::RwD3DRaster` is not declared (`C2039`). This is not a failure of the candidate set; it means the modern SDK's public/core RenderWare headers cannot independently validate the old private D3D raster extension. The earlier successful `0x24`/`+0x1c` probe against the 2014 snapshot remains the relevant SDK corroboration, alongside GTA's constructor/destructor bytes and D3D9 vtable evidence.
