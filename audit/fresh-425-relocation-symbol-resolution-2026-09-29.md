# Fresh 425-body relocation target resolution (2026-09-29)

The current strict 705-object COFF set was rescanned for the 425 bodies assigned to the provisional appended region, then its unresolved references were compared against the latest successful unique-API-thunk diagnostic link map. This is symbol resolution evidence only; diagnostic addresses are not assumed to be production addresses.

## Results

- `audit/appended-thunk-relocation-targets-fresh-425-2026-09-29.json` contains 2,874 COFF relocations: 1,066 REL32 + 34 DIR32 directly target candidate roots; 27 REL32 + 2 DIR32 target another candidate object; 11 REL32 + 224 DIR32 target sections in the same object; and 1,510 are undefined external/alias occurrences.
- The exact-name join `audit/appended-thunk-link-map-resolution-fresh-425-api-thunk-link-2026-09-29.json` finds all 1,510 undefined occurrences in the diagnostic link map. It classifies 293 as diagnostic code, 116 as import slots, 951 as symbols whose names encode an original VA but whose diagnostic providers moved, and 150 as provider/runtime data. There are no exact-name misses in this map join.
- `audit/appended-thunk-original-import-crosswalk-fresh-425-api-thunk-link-2026-09-29.json` matches all 60 candidate import symbols to the original ASI IAT by API name and DLL; none are absent from the original IAT.
- `scripts/audit-address-encoded-coff-targets-in-original-pe.py` and its output `audit/address-encoded-coff-targets-original-pe-section-metadata-fresh-425-2026-09-29.json` check the 441 symbols encoding original VAs against the pinned PE. All 951 reference occurrences fall within mapped sections: 89 in raw-backed `.rdata`, 325 in raw-backed `.data`, and 537 in virtual-only `.data`; zero are outside the original image sections. Original `.data` is RVA `0x29000`, `VirtualSize=0x1455C`, `SizeOfRawData=0x10A00`, characteristics `0xC0000040`; all 537 virtual-only references lie between RVA `0x39A00` (raw end) and `0x3D55C` (virtual end). The PE format specifies that when `SizeOfRawData < VirtualSize`, the remaining section bytes are zero-filled when mapped. This proves their initial zero-fill for an image retaining these section bounds, not their later initialization or semantic roles.
- `scripts/audit-bss-coff-target-ghidra-xrefs.py` joins these virtual-only targets to `audit/candidate-global-ghidra-symbol-xrefs-2026-09-27.csv`. All 147 unique target VAs have Ghidra xref rows. Across those globals, the export records 253 direct WRITE, 31 READ_WRITE, 439 READ, and 250 DATA references; 125 targets have a direct write reference and 100 have a read reference. All recorded source function addresses are exact entries in the 705-function map. Twenty-two target addresses have no explicit WRITE/READ_WRITE xref in this export; `DATA` xrefs and indirect API output parameters are not equivalent to proven initialization.

## What this resolves—and what it does not

No missing-symbol blocker remains for the 425 appended bodies in this diagnostic link. The 951 address-encoded references must still be written as their encoded original addresses, not the shifted diagnostic-map addresses; their VAs are all section-mapped, and Ghidra gives static xrefs for all 147 virtual-only global targets, but this does not prove all initialization paths or dynamic uses. The 116 imports need original IAT-slot values. The 293 code and 150 provider/runtime-data references need explicit final-placement mappings. Same-object and cross-object section targets also need relocation fixups at their actual final destinations. The reports above do not apply any code/data fixup, establish safe executable placement for every provider, modify the original PE, or prove loader/GTA behavior. The output is still not an ASI.
